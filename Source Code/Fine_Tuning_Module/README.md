# 微调数据准备

[项目首页](../../README.md) · [源材料说明](../../docs/paper_with_feedback/kp_for_fine_tuning/README.md)

本目录把专家整理的复合动词材料转换成“要求、输入、参考输出”形式的数据。可以把它理解成未来训练模型时可能使用的教材整理工具。

**目前只有数据预处理，没有训练脚本、微调权重、GPU 配置或训练效果评估。** 文件名包含 `unsloth` 也不表示仓库已经运行了 Unsloth 训练。

## 每个文件的用途

| 文件 | 负责的工作 |
| --- | --- |
| [data_preprocessor.py](data_preprocessor.py) | 读取 Word 段落，按词条标题切分，提取词汇及读音，生成指令样本并写入 JSONL |
| `README.md` | 输入格式、转换步骤和输出含义 |

## 输入与输出

输入为 `docs/paper_with_feedback/kp_for_fine_tuning/84 compound verbs from NINJAL (Updated)_17Nov2025.docx`。

程序通过脚本自己的位置寻找仓库根目录。它读取正文中的非空段落，识别“数字 + 半角句点或全角句点 + 【”形式的词条标题。词汇和读音在方括号中提取，半角括号内内容作为读音，后续段落作为解释。表格、图片内文字和不符合标题规则的内容不会被通用识别。

输出为同目录的 `japanese_vocab_unsloth.jsonl`。当前已提交文件含 84 行，每行是一个 JSON 对象，包含以下三个字段。

| 字段 | 给非开发人员的解释 |
| --- | --- |
| `instruction` | 告诉模型按什么要求回答，例如面向学习者解释复合动词并提供例句 |
| `input` | 本条要解释的词汇和读音 |
| `output` | 从源文档保留的解释与例句，作为参考回答 |

脚本给每条样本添加统一要求，不会自动验证参考回答是否逐项满足这些要求。词条数量也不能代替内容完整性、授权或教学适用性检查。

## 运行步骤

在已经安装依赖的环境中，从仓库根目录执行以下命令。

```sh
python "Source Code/Fine_Tuning_Module/data_preprocessor.py"
```

脚本不调用模型 API，不连接数据库，不需要 GPU。它会覆盖同名 JSONL，运行前先保留原文件或把 `OUTPUT_JSONL` 改为新的输出位置。结束时终端会显示写入的样本数。

转换后应检查样本数、空答案、标题与正文对应、读音解析和参考内容质量。后续训练还需要单独设计训练集与验证集、训练代码、模型许可与硬件配置，以及未见词条上的评价，详见[路线图](../../docs/ROADMAP.md)。
