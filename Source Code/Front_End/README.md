# 桌面界面

[项目首页](../../README.md) · [安装指南](../../docs/SETUP.md)

这个目录负责使用者看到的窗口。当前采用 Python 自带的 Tkinter 桌面技术，程序运行在有图形桌面的电脑上。它不是浏览器网页，没有 npm 安装、前端打包或网站部署步骤。

## 每个文件的用途

| 文件 | 用途 |
| --- | --- |
| [interface.py](interface.py) | 连接 MySQL，创建主窗口和设置窗口，查询学生和试卷，把 Analyze、Generate 操作交给试卷模块 |
| [__init__.py](__init__.py) | Python 包标记，当前为空，不是启动入口 |
| `README.md` | 本目录的运行与操作说明 |

窗口背后的查询、分析和 Word 排版代码位于 [test_paper_generation.py](../Paper_Generator/test_paper_generation.py)。

## 启动前必须完成的准备

1. 按[安装指南](../../docs/SETUP.md)安装 Python 依赖，并用 `python -m tkinter` 验证能够显示窗口。
2. 启动 MySQL，准备兼容的三张表和匿名测试数据，并统一对错字段含义。
3. 由技术同事修改 `interface.py` 顶部数据库连接参数。该文件在创建窗口之前连接数据库，连接失败会使窗口无法出现。
4. 创建一个自己有写入权限的结果文件夹，记下它的绝对路径。
5. 在仓库根目录运行以下命令。

```sh
python "Source Code/Front_End/interface.py"
```

预期出现标题为 `JAP-GPT paper generation` 的小窗口。启动窗口本身不会调用模型 API。

## 操作顺序和按钮含义

| 操作 | 使用者做什么 | 实际发生的工作 |
| --- | --- | --- |
| `setting` | 输入已存在的保存文件夹路径并保存 | 设置本次运行的 Word 输出目录，关闭程序后不会保存这项配置 |
| 输入姓名或学号 | 输入数据库中已有学生的信息 | 此时尚未上传答卷，也没有新增学生 |
| `query` | 点击查询 | 查找学生编号和已有试卷记录，更新下拉列表 |
| 试卷下拉菜单 | 选择该学生已经有作答记录的试卷 | 作为后续分析与抽题范围 |
| `Analyze` | 查看结果窗口 | 展示代码认定的错题、标准答案、学生答案和相关知识点统计；没有 LLM 错误原因解释 |
| `Generate` | 生成补充练习 | 按错题知识点和级别随机查询数据库题目，排版保存 Word；不会现场调用 LLM 出题 |
| 关闭窗口 | 点击关闭 | 关闭数据库连接并结束程序 |

生成结果保存在设置的文件夹中，以试卷名称和版本编号形成文件名。保存成功会弹出提示。代码按错误频次分配目标约 40 题，但取整、多个知识点重复命中、去重、库存不足和旧题干排版规则都可能改变实际题数，不能把 40 当成保证。

## 当前试用限制

- 没有文件上传、用户登录、教师权限管理或班级看板。
- 学生不存在、试卷数据为空、占位选项和保存路径无效等情况尚未完整处理。
- 知识点来自数据库已有标注，不能据此认定已实现自动学情诊断。
- 抽题没有统一的“已审核”过滤状态，也没有完整的已做题排除和复习调度。
- 对错字段存在[跨模块冲突](../../docs/KNOWN_ISSUES.md)，数据核对前不应把统计直接用于学生评价。
- 查询与文件操作直接在界面回调中完成，耗时操作可能让窗口暂时没有响应。

教师可以先查看现有样例了解用途。正式试用应由接手开发者准备通过验证的数据和环境，再提供明确的启动入口。
