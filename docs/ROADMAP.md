# 后续开发方向与建议验收

[项目首页](../README.md) · [安装指南](../SETUP.md)

以下是基于当前代码和项目教学目标提出的后续工作，不代表已实现功能、既定排期或已有实验结论。建议先恢复可靠的小流程，再增加智能化和多人使用能力。

## 阶段一 可靠保存和读取数据

目标是让学生作业和题库成为可信的教学档案。

- 把连接配置集中管理，移除导入模块时删表、处理文件和关闭连接的副作用。
- 统一 `is_correct` 含义、数据库大小写、题号和知识点标记。
- 修复学生更新、题目重复导入、失败重试和 Excel 入库筛选。
- 增加作业、试卷和提交批次，保留同一学生多次作答，记录发生时间。
- 用匿名样例替代交接演示中的个人信息，提供可恢复的测试库准备流程。

验收时使用一个学生、两次作业和已知对错答案。第二次导入后，第一次记录仍可查询；重复导入不会重复计数；对错和知识点统计与手工核对一致。

## 阶段二 建立可审核的高质量题库

目标是把“模型产出的文件”变成“教师可放心选用的教学资源”。

建议扩展的数据包括独立知识点编号、题目版本、标准答案、解释、来源、生成模型与提示词版本、审核人、审核结论和审核时间。草稿、待修改、已通过和已弃用应有明确状态。当前三表结构并未包含这些完整信息。

统一生成、修订和人工评价的 Excel 或结构化接口，保留每次修订前后内容与问题分类。抽题只使用已通过审核的题目，并能追踪来源。入库后仍需要质量回访和撤回机制。

验收时选取一批题目，教师能看到题干、答案、解释和来源，并确认是否通过；被拒绝或待修改题目不会出现在学生练习中。

## 阶段三 打通教学任务流程

目标是让非开发人员通过统一入口完成一次教学任务。

1. 上传符合约定的作业和答案，先支持已有 Word 模板。
2. 预览解析结果，允许教师校正题号、学生答案和知识点。
3. 完成答案比较并保存作答记录。
4. 检索该学生相关历史，让 LLM 提出有依据的薄弱知识点和可能错误原因。
5. 优先从已审核题库抽题，库存不足时才生成新题并进入审核流程。
6. 向学生提供练习和解释，再保存新的作答结果。

API 调用、重试、格式检查和结果保存应由统一 harness 管理。每个任务须显示进度、失败原因、可恢复状态和输出位置；调用失败不能被记录为质量通过。

验收时教师完成一次任务无需修改 Python 文件。中途失败可以重试，不重复保存作答，也不会把未经审核的草稿自动发布给学生。

## 阶段四 长期学习记录与教师分析

目标是让数据库中的历史真正支持持续教学。

- 按知识点聚合作答次数、近期表现、复习间隔和不同题目上的表现。
- 将“证据不足”“偶发错误”和“持续薄弱”区分开，向教师展示依据。
- 支持针对性复习、间隔练习和避免重复曝光同一道题。
- 提供班级共性困难、个体进步和题目质量面板。
- 建立师生角色、数据访问范围、备份和恢复流程。

验收不应只看界面能否画图，还应核对统计是否来自正确的学生和时间范围，以及多次作业能否追溯到原始题目与答案。

## 阶段五 评价和模型改进

目标是用可重复的证据决定是否更换模型、投票策略、提示词、检索或微调方式。

| 评价对象 | 建议评价内容 | 当前结果不能替代的证据 |
| --- | --- | --- |
| 题目质量 | 标准答案正确性、答案唯一性、自然度、知识点匹配、难度适配、教师可接受率 | 文件成功生成或多个模型投票通过 |
| 错题诊断 | 与教师分析的一致性、证据引用、错误原因是否可区分 | 仅统计某知识点答错次数 |
| 修题流程 | 修正原问题的比例、引入新问题的比例、教师修改时间 | 仅统计修改位置一致率 |
| 使用成本 | 每道最终通过题目的调用成本、时延和失败率 | 单次调用耗时或实验组名称 |
| 学习效果 | 在合适教学评价设计下衡量新题表现和知识点掌握变化 | 模型自评或训练集上指标 |
| 微调或检索 | 独立验证集表现、源材料质量、未见词条泛化、基线比较 | 存在 JSONL 文件或训练结束日志 |

可以先尝试检索经审核的知识点说明和题目范例，再研究是否需要微调。现有 84 条复合动词样本可作为数据准备起点，但不能单独证明覆盖面和训练收益。训练与验证应按词条或知识点合理分开，避免近重复材料同时进入两侧。

## 后续可扩展方向

在基础流程可靠后，再考虑 PDF、图片和手写 OCR、开放式回答批改、更多日语级别、听说任务、多语言解释以及学习管理系统对接。每扩展一种输入或任务，都应增加对应解析校验、教师复核和独立评价，而不是沿用选择题答案匹配的成功标准。

## 交接时应明确的责任

| 内容 | 需要交付的结果 |
| --- | --- |
| 数据库维护 | 实际部署位置、维护者、账号分工、备份与恢复方法 |
| 模型 API | 管理者、可用模型和地域、用量查看方式、凭据交接方法 |
| 教学材料 | 来源、授权、审核状态及非技术人员可访问的位置 |
| 开发环境 | 验证过的 Python 与依赖版本、匿名样例、启动命令 |
| 项目范围 | 优先完成的教学场景、验收负责人和可接受的质量标准 |

这些责任需要团队安排，文档不预设由哪位老师或开发者承担。
